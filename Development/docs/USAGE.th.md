# คู่มือ FKP Server Monitor 1.8

## Dashboard และเมนูด้านบน

แถบด้านบนใช้สลับ **แดชบอร์ด**, **รายการเซิร์ฟเวอร์**, **การแจ้งเตือน**, **ตั้งค่าการแจ้งเตือน** และ **อัปเดต / เกี่ยวกับ** ชื่อโปรแกรมคือ **FKP Server Monitor**

การ์ดแสดงชื่อเครื่อง โฮสต์ เวลาตอบกลับ และ SQL ถ้าเปิดตรวจ กราฟใช้ผล Ping จริงล่าสุดไม่เกิน 40 รอบ จุดสีแดงหมายถึงรอบที่ไม่ผ่าน ไม่สร้างข้อมูลแทนผลที่ยังไม่ตรวจ ผลและกราฟเริ่มใหม่เมื่อเปิดโปรแกรม

| สถานะ | ความหมาย |
| --- | --- |
| ผ่าน / เขียว | Ping ผ่าน และ SQL ผ่านด้วยถ้าเปิดตรวจ |
| ฐานข้อมูลมีปัญหา / เหลือง | Ping ผ่าน แต่ตรวจ SQL ไม่ผ่าน |
| DB ใช้ได้ / Ping ไม่ตอบ / เหลือง | SQL ผ่าน แต่ Ping ไม่ผ่าน อาจมีการบล็อก ICMP |
| ไม่ผ่าน / แดง | Ping ไม่ผ่าน และ SQL ไม่ผ่านด้วยถ้าเปิดตรวจ |
| ยังไม่ตรวจ | ยังไม่มีผลที่ตรวจเสร็จ |

คลิกการ์ดเพื่อเลือก ใช้ Ctrl เพื่อเลือกหลายใบ ดับเบิลคลิกเพื่อแก้ไข หรือเลือกหลายแถวในมุมมองรายการ **ตรวจทั้งหมด** ตรวจทั้งรายการแม้ค้นหาอยู่ ส่วน **ตรวจที่เลือก** ใช้รายการที่เลือก ไม่มีการส่งออกรายงาน

## ตรวจ SQL Server เพิ่ม

1. เพิ่มหรือแก้ไขเครื่อง แล้วเลือกแท็บ **SQL Server** และเปิด **ตรวจ SQL Server เพิ่มจาก Ping**
2. ช่อง **SQL Server / Instance** เว้นว่างเพื่อใช้ IP/โฮสต์หลัก หรือระบุ `sql-host\INSTANCE` หรือ `tcp:sql-host,1433` เมื่อ SQL ใช้ปลายทางเฉพาะ
3. ใส่ชื่อฐานข้อมูล ชื่อผู้ใช้ SQL และรหัสผ่าน ใช้ SQL authentication ไม่ใช่ Windows authentication
4. กด **ทดสอบฐานข้อมูล** เพื่อตรวจทันที หรือ **บันทึก** เพื่อใช้ตรวจในรอบถัดไป

เปิดการเชื่อมต่อใหม่ไปยังฐานข้อมูลที่ระบุแล้วรัน `SELECT 1` ไม่เขียนข้อมูล ใช้บัญชีที่มีสิทธิ์เชื่อมต่อและเปิดฐานข้อมูลนั้นเท่าที่จำเป็น ไม่ต้องใช้บัญชีผู้ดูแล SQL ผลผ่านไม่ได้ยืนยันว่าทุกตาราง งานตามเวลา และระบบงานทั้งหมดทำงานถูกต้อง

การเชื่อมต่อเข้ารหัสและตรวจใบรับรองเป็นค่าเริ่มต้น หากใช้ใบรับรองภายใน ให้ผู้ดูแลจัดการใบรับรอง หรือเลือก **เชื่อถือใบรับรอง SQL Server ภายในที่องค์กรจัดการเอง** เฉพาะปลายทางที่ตรวจสอบแล้ว ตัวเลือกนี้ข้ามการตรวจสอบตัวตนของใบรับรอง

แก้ไขแล้วเว้นรหัสผ่านว่างจะใช้รหัสเดิม รหัสที่บันทึกไม่แสดงกลับ SQL ตรวจแยกจาก Ping แม้ Ping หรือ DNS ของโฮสต์หลักไม่ผ่านก็ยังตรวจ SQL ที่กำหนดแยกได้ SQL มีเวลารอของตัวเองและตรวจพร้อม Ping ภายในรอบเดียวกัน

## Outlook / Microsoft 365 — ตั้งค่าภายหลังได้

ค่าเริ่มต้นปิดการส่งทั้ง Outlook และ ntfy โปรแกรมใช้ Microsoft Graph และการลงชื่อเข้าใช้ Microsoft ไม่อ่านโปรไฟล์จาก Outlook desktop และไม่ขอรหัสผ่านอีเมลในโปรแกรม

ผู้ดูแลเตรียมครั้งแรก:

1. ลงทะเบียนแอปใน Microsoft Entra ให้รองรับชนิดบัญชีที่ใช้ หากใช้ Outlook.com ส่วนตัวด้วย ต้องเลือกรองรับ personal Microsoft accounts
2. เปิด **Allow public client flows** ไม่ต้องสร้าง client secret สำหรับการลงชื่อเข้าใช้แบบรหัสอุปกรณ์นี้
3. เพิ่ม Microsoft Graph **Delegated permission: Mail.Send** โปรแกรมขอ `offline_access` เพื่อส่งในครั้งถัดไปด้วย องค์กรอาจต้องอนุมัติสิทธิ์และอาจบล็อก device-code flow ตามนโยบาย
4. คัดลอก **Application (client) ID** มาตั้งค่าในโปรแกรม

ใน **ตั้งค่าการแจ้งเตือน > Outlook / Microsoft 365** ใส่ Client ID, Tenant และผู้รับหลายคนคั่นด้วย `;` ได้สูงสุด 20 รายการ ค่า Tenant `common` ใช้ทั้งส่วนตัวและองค์กรเมื่อแอปรองรับ หรือใช้ Tenant ID/โดเมนองค์กรตามผู้ดูแลกำหนด

กด **ลงชื่อเข้าใช้ Microsoft** โปรแกรมแสดงรหัสและเปิด `https://microsoft.com/devicelogin` คัดลอกรหัสและลงชื่อเข้าใช้ในหน้า Microsoft รอข้อความสำเร็จ แล้วกด **ส่งอีเมลทดสอบ** หากต้องการส่งจริง เปิดตัวเลือกส่งอีเมลและกด **บันทึก**

เปลี่ยน Client ID หรือ Tenant ต้องลงชื่อเข้าใช้ใหม่ หากบัญชีถูกถอนสิทธิ์ให้กลับมาลงชื่อเข้าใช้ใหม่ ข้อความว่า Microsoft รับคำขอแล้วไม่ได้รับประกันว่าผู้รับจะได้รับทันที ตรวจกล่องจดหมายและอีเมลขยะหลังทดสอบ

อ้างอิง: [Microsoft device authorization](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code), [Microsoft Graph sendMail](https://learn.microsoft.com/en-us/graph/api/user-sendmail?view=graph-rest-1.0)

## ntfy

ใน **ตั้งค่าการแจ้งเตือน > ntfy** ใส่ URL เซิร์ฟเวอร์ เช่น `https://ntfy.sh` และ Topic แยกกัน Topic ใช้ตัวอังกฤษ ตัวเลข `_` หรือ `-` สูงสุด 64 ตัว ใส่ access token หากเซิร์ฟเวอร์ต้องยืนยันตัวตน และใช้ HTTPS เมื่อส่ง token ไปยังเครื่องอื่น

สมัครรับ Topic เดียวกันในแอป ntfy บนโทรศัพท์หรือเว็บ กด **ส่ง ntfy ทดสอบ** เพื่อส่งจริง ตรวจว่ารับได้ แล้วเปิดตัวเลือกส่ง ntfy และกด **บันทึก** ช่อง token ว่างคงค่าเดิม ถ้าจะลบให้เลือก **ลบ token เดิมเมื่อบันทึก**

Topic สาธารณะที่ไม่จำกัดสิทธิ์อาจถูกอ่านหรือส่งโดยผู้รู้ชื่อ Topic ควรใช้ชื่อคาดเดายาก หรือ Topic/เซิร์ฟเวอร์ที่กำหนดสิทธิ์ไว้ ข้อความเตือนมีชื่อเครื่อง โฮสต์ และชื่อฐานข้อมูล จึงควรเลือกช่องทางที่เหมาะกับข้อมูลภายใน การที่เซิร์ฟเวอร์รับข้อความแล้วไม่ได้รับประกันว่ามือถือเปิดแจ้งเตือน ตรวจสิทธิ์แจ้งเตือนในโทรศัพท์ด้วย

อ้างอิง: [ntfy publishing](https://docs.ntfy.sh/publish/)

## เงื่อนไขการแจ้งเตือนและข้อมูลบัญชี

Ping และ SQL มีตัวนับแยกกัน ไม่ผ่าน **2 รอบติดต่อกัน** แจ้งปัญหาหนึ่งครั้ง กลับมาผ่านแจ้งฟื้นตัวหนึ่งครั้ง ไม่ส่งซ้ำขณะยังไม่ผ่านต่อเนื่องในช่วงเปิดโปรแกรมเดียวกัน แก้ไขหรือลบรายการจะล้างตัวนับของรายการนั้น

ต้องเปิดตัวเลือกแจ้งเตือนเซิร์ฟเวอร์ใน **การแจ้งเตือน** เพื่ออนุญาตทั้งการแจ้งในโปรแกรมและช่องทางภายนอก Outlook/ntfy เปิดแยกกันได้ ถ้าช่องทางหนึ่งล้มเหลวอีกช่องทางยังส่งได้ ข้อผิดพลาดเก็บในกล่องแจ้งเตือน ไม่มีการส่งซ้ำอัตโนมัติเมื่อผลการส่งไม่แน่นอน คิวระหว่างเปิดโปรแกรมสูงสุด 100 เหตุการณ์และยกเลิกเมื่อปิดโปรแกรม ประกาศผู้พัฒนาแสดงในโปรแกรม ส่วน Outlook/ntfy ส่งเฉพาะเหตุการณ์สถานะเครื่องและฐานข้อมูล

**ต้องเปิดโปรแกรมทิ้งไว้และเปิดตรวจอัตโนมัติจึงเฝ้าดูต่อเนื่อง** เมื่อปิดโปรแกรมหรือเครื่องหลับจะไม่ตรวจหรือส่งเตือน โปรแกรมไม่ได้เป็น Windows service

บัญชีแจ้งเตือนอยู่ใน `alert-settings.json` ข้าง `servers.json` รหัสผ่าน SQL และโทเคนป้องกันด้วย Windows DPAPI เฉพาะ Windows user/เครื่องเดิม ชื่อเครื่อง ฐานข้อมูล อีเมล และ Topic ยังเป็นข้อความปกติ หากย้ายเครื่องหรือ Windows user ให้กรอกรหัส/โทเคนและลงชื่อเข้าใช้ใหม่ ไม่ส่งไฟล์ตั้งค่าที่มีข้อมูลภายในให้ผู้อื่น

ไฟล์ตั้งค่าและ `.bak` เก็บรหัส/โทเคนที่เข้ารหัสแล้ว เมื่ออ่านการตั้งค่าแจ้งเตือนไม่ได้ โปรแกรมปิดช่องทางภายนอกและเก็บไฟล์เดิมไว้ให้กู้คืน ไม่เขียนทับไฟล์เสียอัตโนมัติ

## เริ่มใช้งาน

ดับเบิลคลิก `Program\FKPServerMonitor.exe` และเก็บ `FKPServerMonitor.exe.config` ไว้ข้างกัน ใช้กับ Windows ที่มี .NET Framework 4.8 ขึ้นไป

1. กด **เพิ่มเซิร์ฟเวอร์**
2. ใส่ชื่อ เช่น “เครื่องรายงาน”
3. ใส่ IP หรือชื่อโฮสต์ เช่น `10.0.0.97` หรือ `report-server`
4. กด **บันทึก** แล้วกด **ตรวจทั้งหมด**

ระบุเฉพาะ IP/ชื่อโฮสต์ ไม่ใส่ URL หรือพอร์ต โปรแกรมตรวจด้วย Ping ทุกครั้ง แท็บแรกใช้ชื่อและ IP/โฮสต์ ส่วน SQL Server เปิดตรวจเพิ่มเติมได้ในแท็บแยก

**วางหลายรายการ** ใช้เพิ่ม IP/ชื่อโฮสต์บรรทัดละหนึ่งรายการ รายการซ้ำในข้อความหรือโฮสต์ที่มีอยู่แล้วจะถูกข้าม เลือกแถวแล้วกด **แก้ไข** เพื่อเปลี่ยนชื่อ หรือ **ลบ** เพื่อลบรายการหลังยืนยัน

## อ่าน Dashboard

| สิ่งที่แสดง | ความหมาย |
| --- | --- |
| ผ่าน สีเขียว | ได้รับคำตอบ Ping |
| ไม่ผ่าน สีแดง | ไม่ได้รับคำตอบสำเร็จ เช่น หมดเวลาหรือค้นหาชื่อโฮสต์ไม่ได้ |
| ยังไม่ตรวจ | ยังไม่มีผลการตรวจเสร็จในครั้งที่เปิดโปรแกรมนี้ |
| เวลาตอบกลับ (ms) | เวลาที่ใช้รับคำตอบ Ping หน่วยมิลลิวินาที |
| ตรวจล่าสุด | วันเวลาที่ตรวจรายการนั้นเสร็จ |

เลือกแถวหรือชี้เมาส์ที่เซลล์เพื่อดูข้อความผลลัพธ์และ IP ที่ตรวจจริง ผล “ไม่ผ่าน” อาจเกิดจากไฟร์วอลล์ที่บล็อก Ping ได้ วันที่แสดงเป็น ค.ศ. และเวลาตาม Windows ของเครื่องที่ใช้งาน

## ตรวจด้วยตนเองหรือเป็นรอบ

- **ตรวจทั้งหมด** ตรวจทุกรายการ แม้บางรายการถูกซ่อนด้วยช่องค้นหา
- **ตรวจที่เลือก** ตรวจเฉพาะแถวที่เลือก ใช้ Ctrl/Shift เพื่อเลือกหลายแถว
- **ตรวจอัตโนมัติ** ตรวจทันที จากนั้นเว้นระยะตามจำนวนวินาทีหลังรอบก่อนจบ
- **หยุด** ยกเลิกรอบปัจจุบันและปิดการตรวจอัตโนมัติ รายการที่ยังไม่เสร็จคงผลก่อนหน้า ให้ดูเวลาตรวจล่าสุดประกอบ
- **รอสูงสุด (ms)** กำหนดเวลารอต่อขั้นตอน DNS และต่อคำขอ Ping
- **รอบตรวจ (วินาที)** กำหนดช่วงเว้นระหว่างรอบอัตโนมัติ

ส่ง Ping หนึ่งครั้งต่อเซิร์ฟเวอร์ต่อรอบ และตรวจพร้อมกันสูงสุดแปดรายการ ไม่มีรอบตรวจซ้อนกัน ตรวจอัตโนมัติปิดเมื่อเปิดโปรแกรมใหม่ ช่องค้นหาใช้ค้นชื่อหรือโฮสต์

## ข้อมูลที่บันทึก

รายการและการตั้งค่าอยู่ที่ `%LOCALAPPDATA%\Kuma\ServerBotTracker\servers.json` ของผู้ใช้ Windows ไฟล์ `.bak` เป็นข้อมูลก่อนบันทึกครั้งล่าสุด ผลตรวจไม่ได้เก็บข้ามการเปิดโปรแกรม

รายการจากรุ่นก่อนยังเปิดได้ ชื่อ IP/โฮสต์ และรหัสรายการยังคงเดิม ข้อมูลพอร์ตและวิธีตรวจเดิมเลิกใช้ เมื่อบันทึกตามปกติจะเปลี่ยนเป็นรูปแบบใหม่พร้อมสำรองไฟล์เดิม ไม่มีการรวมรายการเดิมที่ใช้โฮสต์เดียวกันโดยอัตโนมัติ

ย้ายตัวโปรแกรมโดยคัดลอกโฟลเดอร์ `Program` หากต้องการย้ายรายการ ให้ปิดโปรแกรมและคัดลอก `servers.json` ไปยังตำแหน่งเดียวกันของผู้ใช้ปลายทาง โดยสำรองไฟล์ปลายทางก่อนแทนที่

หากข้อมูลเสีย โปรแกรมจะแจ้งข้อผิดพลาดและไม่เขียนทับไฟล์เดิม ปิดโปรแกรมและสำรองข้อมูลก่อนตรวจสอบหรือกู้จาก `.bak`

## อัปเดตและการแจ้งเตือน (รุ่น 1.2)

แนะนำให้ใช้ `FKPServerMonitor-Setup.exe` สำหรับติดตั้งตามปกติ โปรแกรมจะอยู่ใน Start menu ชื่อ **FKP Server Monitor** และถอนการติดตั้งผ่าน Windows ได้ ข้อมูลเซิร์ฟเวอร์เก็บแยกจากตัวโปรแกรม

ปุ่ม **อัปเดต / เกี่ยวกับ** แสดงรุ่นปัจจุบัน สถานะช่องทางเผยแพร่ และตัวเลือกอัปเดตอัตโนมัติ โปรแกรมตรวจเมื่อเปิดและทุกสิบนาที หากมีรุ่นใหม่จะดาวน์โหลดและตรวจสอบไฟล์ แล้วติดตั้งหลังปิดโปรแกรม ปุ่ม **อัปเดตและเริ่มใหม่** ใช้เริ่มใหม่ทันทีหลังติดตั้ง หากก่อนหน้านั้นตรวจ Ping อัตโนมัติอยู่ จะกลับมาตรวจต่อหลังการเริ่มใหม่จากอัปเดต

ปุ่ม **การแจ้งเตือน** แสดงประกาศจากผู้พัฒนาและสถานะเซิร์ฟเวอร์ที่เปลี่ยนไป เมื่อ Ping หรือ SQL ไม่ผ่านสองรอบติดต่อกันจะแจ้งหนึ่งครั้ง โดยนับแยกกัน และแจ้งอีกครั้งเมื่อได้รับคำตอบแล้ว การไม่ผ่านต่อเนื่องจะไม่เตือนซ้ำในช่วงที่เปิดโปรแกรมเดียวกัน ปิดหรือเปิดการแจ้งเตือนเซิร์ฟเวอร์ได้ในหน้านี้

ข้อความเก็บใน `notifications.json` ข้าง `servers.json` สูงสุด 100 รายการ กด **อ่านทั้งหมดแล้ว** เพื่อล้างจำนวนที่ยังไม่อ่าน ประกาศใช้ ID เพื่อไม่แจ้งซ้ำเมื่อเปิดโปรแกรมใหม่ Windows อาจไม่แสดง popup ตามการตั้งค่าของ Windows แต่ข้อความยังอยู่ในกล่องแจ้งเตือน

เมื่อช่องทาง GitHub ยังไม่พร้อมหรืออินเทอร์เน็ตใช้ไม่ได้ โปรแกรมจะแสดงสถานะติดต่ออัปเดตไม่ได้ โดยยังตรวจ Ping ได้ตามปกติ รายการเซิร์ฟเวอร์และข้อความเตือนภายในไม่ได้ส่งไปยัง GitHub ผู้ใช้ชื่อ Server Bot Tracker เดิมต้องเปิด Setup ใหม่นี้หนึ่งครั้ง เพื่อย้ายตัวถอน ทางลัด และรายการ Control Panel ไปใช้ชื่อใหม่

การออกเวอร์ชันและประกาศสำหรับเจ้าของโปรแกรมดู [คู่มือเผยแพร่](RELEASES.th.md)

## ตัวติดตั้งและถอนการติดตั้งรุ่น 1.6

เปิด `FKPServerMonitor-Setup.exe` แล้วทำตามขั้นตอน:

1. กด **ถัดไป** เพื่อเปิดหน้า **เลือกโฟลเดอร์ติดตั้ง**
2. กด **เรียกดู...** เลือกไดรฟ์หรือโฟลเดอร์หลัก ระบบเพิ่มโฟลเดอร์ `FKP Server Monitor` ให้ เช่น เลือกไดรฟ์ D: จะเป็น `D:\FKP Server Monitor` ไม่ต้องสร้างโฟลเดอร์เอง หรือพิมพ์พาธเต็มที่ต้องการ
3. กด **ถัดไป** ตรวจตำแหน่ง แล้วกด **ติดตั้ง** หากต้องการแก้ไขให้กด **ย้อนกลับ** จากนั้นอนุญาตหน้าต่างสิทธิ์ผู้ดูแลระบบของ Windows
4. เมื่อติดตั้งสำเร็จเลือกว่าจะเปิดโปรแกรมหรือไม่ แล้วกด **เสร็จสิ้น**

ตัวติดตั้งสร้างโฟลเดอร์ปลายทางให้เมื่อกด **ติดตั้ง** หากเลือกโฟลเดอร์ `FKP Server Monitor` หรือโฟลเดอร์ที่มีโปรแกรมเดิมอยู่แล้ว จะไม่เพิ่มชื่อซ้ำอีกชั้น หากพิมพ์ `D:` หรือ `D:\` ระบบเปลี่ยนเป็น `D:\FKP Server Monitor` โดยอัตโนมัติ ตรวจพาธสุดท้ายในหน้ายืนยันก่อนเริ่มติดตั้ง

ตำแหน่งเริ่มต้นคือ `%ProgramFiles%\FKP Server Monitor` ซึ่งปกติเป็น `C:\Program Files\FKP Server Monitor` ติดตั้งสำหรับทุกคนในเครื่องและเพิ่มทางลัด Start menu สำหรับทุกคน Windows จะขอสิทธิ์ผู้ดูแลระบบตอนเริ่มติดตั้ง หากเลือก No จะยังไม่เปลี่ยนไฟล์โปรแกรม กด **ลองอีกครั้ง** เมื่อต้องการอนุญาต ห้ามเลือกโฟลเดอร์ที่มีไฟล์โปรแกรมอื่นชื่อซ้ำ ตัว Dashboard ใช้สิทธิ์ผู้ใช้ปกติ

เปิด Setup ครั้งถัดไปจะจำตำแหน่งที่ลงทะเบียนสำหรับเครื่องนี้ ทางลัด Start menu ตัวถอนใน Control Panel และอัปเดตใช้ตำแหน่งที่เลือก รายการเซิร์ฟเวอร์ยังอยู่ใน LocalAppData แยกตามผู้ใช้เหมือนเดิม หลังติดตั้งแบบใหม่สำเร็จ จะนำรายการติดตั้ง ทางลัด และไฟล์โปรแกรมรุ่นเก่าเฉพาะผู้ใช้คนเดิมออก โดยเก็บไฟล์ที่ไม่เกี่ยวข้องไว้ หากสำเนาเก่าถูกใช้งานจะแจ้งว่ายังเก็บสำเนานั้นไว้และรุ่นใหม่ติดตั้งสำเร็จแล้ว

โปรแกรมจะแสดงความคืบหน้าและป้องกันการปิดระหว่างเปลี่ยนไฟล์ หากเกิดข้อผิดพลาดจะแสดงสาเหตุและปุ่ม **ลองอีกครั้ง**

ถอนการติดตั้งจาก **Control Panel > Programs and Features > FKP Server Monitor > Uninstall/Change** กด **ถัดไป** แล้ว **ถอนการติดตั้ง** ตัวช่วยจะแสดงผลก่อนให้กด **เสร็จสิ้น** หากโปรแกรมยังเปิดอยู่ให้ปิดโปรแกรมแล้วลองอีกครั้ง ไฟล์รายการเซิร์ฟเวอร์ การตั้งค่า และไฟล์อื่นที่ไม่เกี่ยวข้องจะยังคงอยู่

รุ่น **1.6** ขอสิทธิ์ผู้ดูแลระบบก่อนนำโปรแกรมที่ติดตั้งสำหรับทุกคนออก และตรวจไฟล์โปรแกรม/ทางลัดทั้งหมดก่อนเปลี่ยนไฟล์ หากไฟล์ถูกใช้งานจะหยุดก่อนนำไฟล์ออก หากเกิดข้อผิดพลาดระหว่างขั้นตอน ระบบพยายามคืนไฟล์และรายการโปรแกรมเดิม แล้วแจ้งผลตามจริง หากคืนได้ไม่ครบจะระบุตำแหน่งสำรองให้กู้คืน ข้อความผิดพลาดเลื่อนและคัดลอกได้

กรณีถอนโปรแกรมเสร็จแล้วแต่ยังลบไฟล์ชั่วคราวไม่ได้ จะแสดง **ถอนการติดตั้งเสร็จสมบูรณ์** พร้อมรายละเอียดไฟล์ชั่วคราว ไม่แจ้งว่าโปรแกรมยังถอนออกไม่ได้ ทั้งที่ลบแล้ว

ตั้งแต่รุ่น **1.5.2** สามารถดับเบิลคลิก **Uninstall.exe** ภายในโฟลเดอร์ที่ติดตั้งได้โดยตรง แล้วกด **ถัดไป > ถอนการติดตั้ง** รุ่นก่อนหน้านี้เปิดไฟล์นี้โดยตรงแล้วเข้าโหมดติดตั้งผิด ทำให้เกิดข้อความว่าไฟล์กำลังถูกใช้งาน ให้ใช้ Control Panel หรือเปิด Setup รุ่นล่าสุด แล้วเลือกโฟลเดอร์เดิมเพื่อติดตั้งตัวถอนรุ่นแก้ไขก่อน ระบบอัปเดตอัตโนมัติไม่เปลี่ยน Uninstall.exe

ผู้ที่มีรุ่นก่อนหน้าให้เปิด Setup รุ่น 1.7 หนึ่งครั้งเพื่อเปลี่ยนเป็นการติดตั้งแบบมาตรฐานพร้อมตัวถอนรุ่นใหม่ ระบบอัปเดต ZIP ยังคงอัปเดตเฉพาะโปรแกรมสองไฟล์ตามเดิม

อัปเดตของโปรแกรมที่ติดตั้งใน Program Files จะดาวน์โหลดอัตโนมัติ แล้วขอสิทธิ์ผู้ดูแลระบบเมื่อติดตั้ง หากไม่อนุญาตจะเก็บโปรแกรมเดิมและแจ้งในกล่องการแจ้งเตือน การเริ่มโปรแกรมใหม่หลังอัปเดตใช้สิทธิ์ผู้ใช้ปกติ ไม่มีการบังคับให้ Dashboard รันเป็นผู้ดูแลระบบตลอดเวลา

ไอคอนหุ่นยนต์ที่เจ้าของให้มาใช้กับไฟล์โปรแกรม ตัวติดตั้ง หน้าต่าง ระบบแจ้งเตือน และทางลัด Start menu โดยฝังไว้ใน EXE ไม่ต้องแจกไฟล์รูปแยก สีเดิมของโปรแกรมยังคงเดิม

## เปลี่ยนชื่อในรุ่น 1.7

โปรแกรมใช้ชื่อ FKP Server Monitor เปิดตัวติดตั้ง FKPServerMonitor-Setup.exe หนึ่งครั้งเพื่อเปลี่ยนจากชื่อเดิม หากมีโปรแกรมเดิมอยู่แล้ว ให้เลือกโฟลเดอร์ติดตั้งเดิมเพื่อแทนที่ไฟล์และทางลัดอย่างปลอดภัย โฟลเดอร์เริ่มต้นสำหรับการติดตั้งใหม่คือ C:\Program Files\FKP Server Monitor ตัวติดตั้งจะจำตำแหน่งที่เคยเลือก รายการเซิร์ฟเวอร์และการแจ้งเตือนยังอยู่ที่เดิม ไม่ต้องเพิ่มรายการใหม่ ระบบอัปเดตอัตโนมัติใช้ช่องทางของชื่อใหม่หลังติดตั้งรุ่นนี้
